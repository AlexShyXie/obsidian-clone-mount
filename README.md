# Clone Mount

**在 Obsidian 原生文件树里模拟 Trilium 的克隆（branch）**：把同一个笔记或文件夹"挂"到文件树的多个位置——单一文件源、零复制、磁盘零改动。

```
教材/
  系统解剖学.md            ← 唯一的真实文件
分类/
  技术栈/
    ⎇ 系统解剖学.md        ← 克隆挂载：点击 = 打开同一个文件
  中间件/
    ⎇ 影像科视角           ← 同一文件第二处挂载 + 独立别名
```

## 功能概览

| 功能 | 对应 Trilium 概念 | 说明 |
|---|---|---|
| **克隆挂载** | branch | 右键任意笔记 → "克隆挂载到文件夹…"，同一个笔记出现在树的多个位置；一处编辑、处处同步（本来就是同一个文件） |
| **文件夹挂载** | 子树克隆 | 右键任意文件夹 → "克隆挂载文件夹到…（整棵子树）"，锚点下出现虚拟文件夹，展开可浏览其全部子内容 |
| **摘除挂载** | DELETE branch | 右键虚拟条目 → 摘除。只解除这一处的挂载，**永远不删除文件**（真实位置始终兜底，无 Trilium "末位 branch 连删" 陷阱） |
| **挂载别名** | branch prefix | 右键虚拟条目 → "重命名此挂载的显示名…"。仅这一处挂载显示新名字并按新名排序；真实文件名与其他位置不受影响 |
| **在真实位置显示** | — | 右键虚拟条目 → 展开折叠的祖先目录链，滚动定位到真实条目并闪烁 |
| **当前文件高亮** | — | 打开任一文件，它在所有挂载点的条目同步高亮 |

**核心保证**：挂载是纯引用（`data.json` 存路径表），不移动、不复制、不写入任何文件；卸载插件 = 树回到原状。

## 语义对照

| Trilium | Clone Mount |
|---|---|
| noteId（笔记身份） | 磁盘 path（唯一真实文件） |
| branch(parent, note) | 挂载记录（锚点文件夹 → 条目路径），多对多 |
| 首要 branch | 真实磁盘父目录 |
| 克隆子树 | 文件夹挂载（递归显示全部子内容 + 挂到子文件夹的独立挂载） |
| DELETE branch（仅末位才删 note） | 摘除挂载——**任何情况下都不删文件** |
| branch prefix | 挂载别名（per-branch，不串位置） |
| 移动到 branch 父下 | 原生拖拽/移动进锚点文件夹 → 挂载自动解除（真实条目已在场） |

## 安装

1. 将 `clone-mount/` 整个文件夹复制到 `<你的库>/.obsidian/plugins/` 下
2. 设置 → 第三方插件 → 刷新 → 启用 "Clone Mount"
3. 无任何配置，右键任一笔记即出现挂载入口

**系统要求**：Obsidian 1.14+，桌面与移动端（双端 1.15.0 实测通过；Explorer 需为默认核心插件）。移动端右键=长按。

## 使用

### 入口

- **原生右键任意笔记/文件夹** → "克隆挂载到文件夹…" / "克隆挂载文件夹到…"（模态框支持路径模糊搜索）
- **右键虚拟条目**（带 ⎇ 分支小图标的条目）→ 打开 / 在真实位置显示 / 重命名显示名 / 摘除挂载
- **命令面板**（Ctrl+P）：
  - `挂载：把当前笔记/文件夹挂到某文件夹（克隆）`
  - `挂载：摘除当前笔记的全部挂载`
  - `挂载：重建全部虚拟条目（排障用）`

### 行为规则

- 点击虚拟条目 = 打开真实文件（编辑器、标签、链接行为全原生）
- 重命名/移动真实文件 → 所有挂载自动跟随新路径
- 删除真实文件 → 相关挂载自动清理
- 把真实文件拖进锚点文件夹（原生移动）→ 该挂载自动解除（对应"移到 branch 父下"）
- 文件夹不能挂到它自己的子文件夹下（防递归环，运行时对账同样清理）
- 虚拟文件夹默认折叠、展开才渲染子内容（懒加载）；折叠状态会话内保持
- 挂载进虚拟子文件夹的笔记，在整棵子树的所有出现位置可见（同 Trilium）

## 数据格式

`.obsidian/plugins/clone-mount/data.json`：

```json
{
  "mounts": { "分类/技术栈": ["教材/系统解剖学.md", "教材/生理学"] },
  "labels": { "分类/技术栈|教材/系统解剖学.md": "影像入门" }
}
```

纯路径引用，可读可手改；`labels` 为可选平行表（别名），两者向后兼容。

## 架构与已知边界（如实披露）

**只虚拟化条目，不虚拟化文件夹节点**：锚点是真实磁盘文件夹（空目录即可），只有"条目"是虚拟的——原生排序、折叠、搜索、拖拽对真实树的行为全部保留。

**虚拟条目只活在文件树（Explorer）视图内**：全局搜索、快速切换、反向链接面板、"最近文件"等旁路场景只认真实路径——这是 Obsidian 磁盘映射架构的边界，模拟不掉。

**其他边界**：

- Explorer 搜索框过滤时虚拟条目行为未定义
- 虚拟条目不支持拖拽（原生拖拽语义 = 真实移动，与挂载语义冲突，刻意禁用）
- 虚拟子树不参与 1.15 虚拟滚动的视口回收：挂载超大文件夹（数百条目）时展开会比原生略卡（懒渲染 + 默认折叠已缓解）
- 虚拟文件夹内不支持原生新建笔记落到虚拟位置；排序固定"文件夹前 + 名称"
- 挂载表存路径 + rename 事件维护；OB 未运行期间的外部移动由渲染期对账兜底
- 多 workspace / 多个文件树 leaf 并存时只取第一个

**失败模式（设计保证）**：任何 Obsidian 升级导致内部结构不兼容时——控制台 `[clone-mount]` 警告 + 一次 Notice，**文件树不坏、文件不动**，挂载数据保留在 `data.json`，禁用/卸载插件即完全恢复原状。

**兼容性原理（供维护者）**：视图获取走官方 API（`getLeavesOfType('file-explorer')`）；原生右键入口走官方事件（`workspace.on('file-menu')`）；vault 事件走官方 API。唯一涉及内部结构的是往 `fileItems[锚点].childrenEl` 插入对齐原生 `nav-file/nav-folder` class 体系的 DOM，以及对 1.15 InfinityScroll `setChildrenInPlace`/`empty` 清除机制的定向 after-patch（原生操作后同步重插，无反馈循环）。

## 自查清单（安装后 5 分钟验证）

| # | 操作 | 预期 |
|---|---|---|
| 1 | 建一个空文件夹，右键某笔记挂到它 | 文件夹下出现带 ⎇ 图标的虚拟条目，真实文件不动 |
| 2 | 点击虚拟条目、编辑保存 | 打开的正是该笔记；内容即本体 |
| 3 | 右键虚拟条目 → 摘除挂载 | 条目消失，文件原位完好 |
| 4 | 折叠目标笔记的父目录，右键虚拟条目 → 在真实位置显示 | 祖先链逐级展开、定位并闪烁 |
| 5 | 右键文件夹挂载 → 展开 | 子内容完整可浏览；点其中文件 = 打开真实文件 |
| 6 | 给挂载条目改名 | 仅该处显示新名并重排序，悬停见原名 |
| 7 | 大幅滚动文件树、连续切换文件 | 虚拟条目稳定不消失 |
